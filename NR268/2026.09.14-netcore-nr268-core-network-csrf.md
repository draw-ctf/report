# Cross-Site Request Forgery on Core Network Configuration CGI Routes

- Published: 2026-09-14
- Supplier: Netcore
- Product: NR268
- Affected version: NR268-V1.7.121109.bin
- Vulnerability type: Cross-Site Request Forgery (CSRF)
- Contributors: Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary
WAN/LAN/routing/NAT/VLAN/DMZ/UPnP setters forward form fields to cgi_SwitchCall without Origin, Referer, or nonce checks.

## Affected Component / Code Path
- `/router/wan_config_set.cgi`
- `/router/routing_tab_add.cgi`
- `/router/route_policy_add.cgi`
- `/router/virtual_service_add_del.cgi`
- `/router/igd_access_mode.cgi`

## Technical Details
Mutating handlers read business parameters with get_form_value and immediately call cgi_SwitchCall. They sit behind HTTP Basic authentication only.

## Verification
- Tested firmware: `NR268-V1.7.121109.bin`
- Authentication: Victim browser with cached management Basic authentication
- Replace `DEVICE`, `USER`, and `PASS` with a lab device and a management account.

```
curl -sS -u USER:PASS -X POST -d 'iface=wan1' http://DEVICE/router/wan_config_set.cgi
```

Expected result: The setter is accepted without Origin/Referer/token validation.

These steps are for vendor/CNA verification on a lab device. They are not a full exploit chain.

## Impact
A logged-in administrator visiting a hostile page can have WAN, routing, NAT, or access-mode settings changed.
