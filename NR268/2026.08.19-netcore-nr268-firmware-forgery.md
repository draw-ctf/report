# Forgeable Firmware Authenticity Check in mtd_write

- Published: 2026-09-14
- Supplier: Netcore
- Product: NR268
- Affected version: NR268-V1.7.121109.bin
- Vulnerability type: Improper Integrity Verification
- Contributors: Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary
Firmware upload accepts an image when a header digest matches MD5 of MD5 of the payload concatenated with a hardcoded constant, not a vendor signature.

## Affected Component / Code Path
- `/router/put_file.cgi`
- `/bin/mtd_write`
- `check_image_uuid.c`

## Technical Details
put_file.cgi forwards the image to mtd_write. The helper accepts the image when header bytes 0x20-0x2f equal MD5(MD5(file[0x50:]) || hardcoded constant). There is no public-key signature, HMAC, or device-bound secret.

## Verification
- Tested firmware: `NR268-V1.7.121109.bin`
- Authentication: Management authentication when the upgrade route is protected; otherwise anyone who can reach put_file.cgi
- Replace `DEVICE`, `USER`, and `PASS` with a lab device and a management account.

```
curl -sS -u USER:PASS -F 'put_file=@forged.bin' http://DEVICE/router/put_file.cgi
```

Expected result: An image whose header digest is recomputed from the hardcoded check is accepted. Do not flash a destructive image on a production device.

These steps are for vendor/CNA verification on a lab device. They are not a full exploit chain.

## Impact
An attacker who can reach the upgrade route can install attacker-controlled firmware.
