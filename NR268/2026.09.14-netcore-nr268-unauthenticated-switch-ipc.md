# Missing Authentication on the Switch Daemon IPC Control Plane

- Published: 2026-09-14
- Supplier: Netcore
- Product: NR268
- Affected version: NR268-V1.7.121109.bin
- Vulnerability type: Missing Authentication for Critical Function
- Contributors: Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary
The switch daemon IPC server accepts local clients and dispatches privileged SwitchCall actions with no peer authentication.

## Affected Component / Code Path
- `switch daemon IPC`
- `SwitchCall dispatcher`

## Technical Details
The daemon binds a well-known UNIX-domain socket, accepts arbitrary local clients, and passes parsed requests into the privileged dispatcher with no UID or protocol-level authentication. This bypasses the HTTP Basic authentication boundary used by the web UI.

## Verification
- Tested firmware: `NR268-V1.7.121109.bin`
- Authentication: Local process on the device; no web login required
- Replace `DEVICE`, `USER`, and `PASS` with a lab device and a management account.

```
# local IPC, not HTTP. Connect to the SwitchCall UNIX socket and send a framed request with payload_len, opcode, and param_count.
```

Expected result: The dispatcher handles the request without authenticating the peer.

These steps are for vendor/CNA verification on a lab device. They are not a full exploit chain.

## Impact
A local process can change routing and interface state without web credentials.
