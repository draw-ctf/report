# Cross-Site Request Forgery on Privileged Management CGI Actions

- Published: 2026-09-14
- Supplier: Netcore
- Product: NR268
- Affected version: NR268-V1.7.121109.bin
- Vulnerability type: Cross-Site Request Forgery (CSRF)
- Contributors: Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary
Privileged state-changing CGI routes accept POST requests after Basic authentication only and do not bind the request to a same-origin token.

## Affected Component / Code Path
- `/router/reboot.cgi`
- `/router/RestoreDefault.cgi`
- `/router/UserPassSet.cgi`
- `/router/WebPortSet.cgi`
- `/router/WebRemotePortSet.cgi`

## Technical Details
reboot.cgi, RestoreDefault.cgi, UserPassSet.cgi, WebPortSet.cgi, and WebRemotePortSet.cgi do not validate Origin, Referer, or an anti-CSRF token. UserPassSet.cgi does not require the current administrator secret. Browsers may automatically attach cached Basic credentials.

## Verification
- Tested firmware: `NR268-V1.7.121109.bin`
- Authentication: Victim browser with cached management Basic authentication
- Replace `DEVICE`, `USER`, and `PASS` with a lab device and a management account.

```
curl -sS -u USER:PASS -X POST -d 'noneed=noneed' http://DEVICE/router/reboot.cgi
curl -sS -u USER:PASS -X POST -d 'password=NewPass' http://DEVICE/router/UserPassSet.cgi
```

Expected result: The request is accepted without an anti-CSRF token. Prefer observing a non-destructive route first.

These steps are for vendor/CNA verification on a lab device. They are not a full exploit chain.

## Impact
A logged-in administrator who visits a hostile page can be induced to reboot, factory-reset, change the admin secret, or change management ports.
