# Netcore NR268 Stack-Based Buffer Overflow in ntools_info_show.cgi

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Stack-based Buffer Overflow (CWE-121 / CWE-787)  
**Credits:** Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary

`ntools_info_show.cgi` allocates a 1048-byte stack buffer `v37`, advertises a 1041-byte backend length, and passes that pointer into `cgi_SwitchCall(157)`. The switch-side `ntools_proc` handler then unconditionally `memset(a2, 0, 0x423)` before any active-tool check. A single authenticated request overwrites 11 bytes past the caller buffer and corrupts CGI stack memory.

## Technical Details

The CGI caller allocates `char v37[1048]` (`0x418` bytes) and tells the backend the buffer is 1041 bytes long. `ntools_proc` ignores that length and clears `0x423 = 1059` bytes into the same pointer:

```
memset(a2, 0, 0x423)   // 1059 bytes
sizeof(v37) == 0x418   // 1048 bytes
overrun = 0x423 - 0x418 = 11 bytes
```

The oversized `memset` runs before any tool-state inspection, so the overflow is reached on the first authenticated POST to the route with an `applet` form value.

### Affected Endpoint

- URL: `/router/ntools_info_show.cgi`
- Parameters: `applet` (for example `ping`)
- Method: POST
- Authentication: HTTP Basic authentication

## Proof of Concept

```bash
curl -s -u admin:admin -X POST "http://192.168.1.1/router/ntools_info_show.cgi" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "applet=ping"
```

### Outcome

The switch-side handler writes 1059 zero bytes into the 1048-byte CGI stack buffer. Adjacent CGI stack state is overwritten by 11 bytes. The worker may crash, reset the connection, or return an abruptly broken response.

## Impact

- **Confidentiality:** Low
- **Integrity:** Medium – adjacent stack data is corrupted
- **Availability:** High – CGI worker crash / denial of management actions

A single authenticated request is enough to corrupt CGI stack memory. Combined with a follow-up attacker-controlled write, the same primitive can overwrite adjacent stack data.
