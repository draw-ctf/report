# Stack-Based Buffer Overflow in ntools_info_show.cgi

- Published: 2026-09-14
- Supplier: Netcore
- Product: NR268
- Affected version: NR268-V1.7.121109.bin
- Vulnerability type: Stack-Based Buffer Overflow
- Contributors: Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary
ntools_info_show.cgi allocates a 1048-byte stack buffer but the switch-side ntools_proc handler writes 0x423 bytes, overflowing the caller buffer.

## Affected Component / Code Path
- `/router/ntools_info_show.cgi`
- `ntools_proc`

## Technical Details
The CGI advertises a backend length of 1041 and calls cgi_SwitchCall(157). ntools_proc then unconditionally writes 0x423 bytes before any active-tool check, overwriting at least 11 bytes past the stack buffer. A long applet value is not required.

## Verification
- Tested firmware: `NR268-V1.7.121109.bin`
- Authentication: HTTP Basic authentication, valid management account
- Replace `DEVICE`, `USER`, and `PASS` with a lab device and a management account.

```
curl -sS -u USER:PASS -X POST -d 'applet=ping' http://DEVICE/router/ntools_info_show.cgi
```

Expected result: Stack memory past the 1048-byte buffer is overwritten. Watch for CGI crash or a broken response.

These steps are for vendor/CNA verification on a lab device. They are not a full exploit chain.

## Impact
Authenticated requests can corrupt CGI stack memory and disrupt the management service.
