# Netcore NR268 DDNS Secret Disclosure

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Cleartext Storage / Information Disclosure (CWE-312 / CWE-200)  
**Credits:** Zhou Ao, Zhang Yu, Yang Yang, Liu Xin @Nebusec

## Summary

`ddns_wan_list_show.cgi` fetches configured DDNS records and appends both `user_idN` and `passwordN` directly into the JSON response. The web UI then writes those values back into the DDNS form, so any authenticated web client can recover provider credentials instead of a masked placeholder. An ordinary POST with `noneed=noneed` is sufficient: the handler treats stored DDNS secrets as readable configuration rather than write-only values, exposing reusable provider usernames and passwords to anyone with a management session.

## Technical Details

The show handler calls `cgi_SwitchCall(216, ...)` and serializes stored usernames and passwords with `%s`. No masking, omission, or reset-only handling is applied. The frontend `html_load_ddns` repopulates `#ddns_user_id` and `#ddns_user_password` from the returned fields.

### Affected Endpoint

- URL: `/router/ddns_wan_list_show.cgi`
- Parameters: `noneed=noneed`
- Method: POST
- Authentication: HTTP Basic authentication

## Proof of Concept

```bash
curl -s -u admin:admin -X POST "http://192.168.1.1/router/ddns_wan_list_show.cgi" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "noneed=noneed"
```

### Outcome

The HTTP 200 JSON body includes `user_idN` and `passwordN` with the stored plaintext DDNS credentials, not a masked placeholder.

## Impact

- **Confidentiality:** High – DDNS provider usernames and passwords are exposed.
- **Integrity:** Low
- **Availability:** Low

An authenticated attacker can reuse the recovered credentials to take over the DDNS hostname mapping outside the router.
