# Netcore NR268 Stored Cross-Site Scripting in DHCP/DNS Management Pages

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Stored Cross-Site Scripting (XSS) (CWE-79)  
**Credits:** Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary

Several DHCP/DNS routes serialize attacker-controlled strings with `%s` into pseudo-JSON, and the web UI parses the response with `eval('('+data+')')`. The strongest case is `dhcp_dynamicip_show.cgi`: DHCP client hostnames are stored without quote escaping and later executed in the administrator browser. The same unescaped reflection pattern is reused for static DHCP names, dnsmasq hosts, IP-DNS rule names, and DDNS fields.

## Technical Details

`write_lease()` rejects only bytes below `0x21` and `0x7f`, so quote characters and markup survive. `dhcp_dynamic_ip_dump()` copies those hostnames into the status buffer, and `dhcp_dynamicip_show_cgi` emits them unescaped. `DataRequest` parses the response with `eval('('+data+')')`, and the status renderer concatenates cell values into HTML and injects them via `innerHTML`.

An unauthenticated LAN client can therefore persist JavaScript by choosing a DHCP hostname such as `<svg/onload=alert(1)>` or `","x":(globalThis.p=1),"y":"`. When an administrator opens the DHCP status page, the payload executes in the router origin.

### Affected Endpoint

- URL: `/router/dhcp_dynamicip_show.cgi`, `/router/dhcp_staticip_show.cgi`, `/router/dhcp_add_staticip.cgi`, `/router/dnsmasq_host_show.cgi`, `/router/dnsmasq_add_host.cgi`, `/router/ip_dns_show.cgi`, `/router/ip_dns_set.cgi`, `/router/ddns_wan_list_show.cgi`
- Parameters: stored name/hostname/user fields serialized with `%s`
- Method: POST
- Authentication: LAN DHCP hostname needs no web auth; list/show routes use HTTP Basic authentication

## Proof of Concept

From a LAN client, request a DHCP lease with hostname `<svg/onload=alert(1)>`. Then, as administrator:

```bash
curl -s -u admin:admin -X POST "http://192.168.1.1/router/dhcp_dynamicip_show.cgi" \
  -d "noneed=noneed"
```

A quote-bearing hostname that breaks the `eval` parser:

```text
","x":(globalThis.p=1),"y":"
```

The management page executes `eval('('+data+')')` on the raw reply and renders table cells with `innerHTML`.

### Outcome

The JSON-like response contains the unescaped hostname. Opening the DHCP status page executes the stored script in the administrator browser (`eval` breakout and/or SVG/`innerHTML` injection).

## Impact

- **Confidentiality:** High – administrator session in the router origin can be stolen.
- **Integrity:** High – attacker script runs with administrator privileges in the management UI.
- **Availability:** Low

An unauthenticated LAN client, or an authenticated user who can store DHCP/DNS names, can persist JavaScript that executes when an administrator opens the affected pages.
