# Netcore NR268 Boa Authentication Fails Open When the Auth Cache Is Missing

**Vendor:** Netcore  
**Product:** NR268 Router  
**Affected Version:** NR268-V1.7.121109.bin  
**Vulnerability Type:** Improper Authentication (CWE-287)  
**Credits:** Zhou Ao, Zhang Yu, Yang Yang, Liu Xin @Nebusec

## Summary

Boa reads credentials from `/tmp/passwd`, and `user_ok()` returns success when that lookup fails. `process_header_end()` treats any positive `user_auth()` result as authorized and continues into CGI execution. While `/tmp/passwd` is missing or malformed, any HTTP Basic header is accepted on the `/router/*.cgi` surface, including privileged write actions. Representative probes against `/router/WebPortSet_show.cgi` and `/router/WebRemotePortShow.cgi` with wrong credentials reach the CGI path instead of returning 401.

## Technical Details

`get_password()` opens `/tmp/passwd`, expects a first line containing `name=` and a second line containing `password=`, and otherwise returns `-1`. `user_ok()` treats that `-1` as success by returning `1`. `user_auth()` then sets its return value to `1` whenever a `Basic` header is present and `user_ok()` is non-zero.

`process_header_end()` sends any positive auth result down the authorized CGI path (`init_cgi()` / `init_get()`). The only explicit rejection path is `user_auth() == -1` followed by `send_r_unauthorized()`. Wrong credentials therefore reach CGI instead of returning 401 when the cache file is missing or malformed.

The `switch` daemon separately maintains the same credential cache from `/tmp/igd_webs_param.file`. On load failure it seeds both cached fields with `guest` and writes `name=guest` / `password=guest` back to `/tmp/passwd`, so the fail-open state is not self-correcting.

### Affected Endpoint

- URL: `/router/WebPortSet_show.cgi`, `/router/WebRemotePortShow.cgi`
- Coverage: the fail-open applies to the full `/router/*.cgi` surface, including privileged write actions
- Method: POST
- Authentication: any HTTP Basic header is accepted while `/tmp/passwd` is missing or malformed

## Proof of Concept

On the device, corrupt or remove the auth cache:

```sh
mv /tmp/passwd /tmp/passwd.bak
# or: printf 'name=broken\n' > /tmp/passwd
```

Then from the attacker host:

```bash
curl -sv -u baduser:badpass -X POST \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "noneed=noneed" \
  "http://192.168.1.1/router/WebPortSet_show.cgi"

curl -sv -u baduser:badpass -X POST \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "noneed=noneed" \
  "http://192.168.1.1/router/WebRemotePortShow.cgi"
```

### Outcome

The wrong-credential POST reaches the CGI path and returns configuration data (HTTP 200) instead of `401 Unauthorized`. The same fail-open covers privileged write routes such as reboot, factory reset, administrator credential change, firmware upload, and parameter restore.

## Impact

- **Confidentiality:** High
- **Integrity:** High
- **Availability:** High

While `/tmp/passwd` is missing or malformed, anyone who can reach the management plane can invoke `/router/*.cgi` with an arbitrary Basic header. If credential-cache rebuild then fails, `switch` reseeds `guest/guest`.
