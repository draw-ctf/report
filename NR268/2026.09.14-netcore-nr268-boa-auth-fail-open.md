# Boa Authentication Fails Open When the Auth Cache Is Missing

- Published: 2026-09-14
- Supplier: Netcore
- Product: NR268
- Affected version: NR268-V1.7.121109.bin
- Vulnerability type: Improper Authentication
- Contributors: Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary
Boa treats a failed lookup of the local authentication cache as success, so a missing or malformed cache opens the CGI surface.

## Affected Component / Code Path
- `Boa user_ok`
- `process_header_end`
- `/router CGI surface`

## Technical Details
user_ok() returns success when the local auth cache lookup fails. process_header_end() treats any positive user_auth() result as authorized. The switch daemon reseeds a default guest account on load failures. While that state persists, privileged CGI actions are reachable without a valid administrator account.

## Verification
- Tested firmware: `NR268-V1.7.121109.bin`
- Authentication: None, but only while the shared auth cache is missing or malformed
- Replace `DEVICE`, `USER`, and `PASS` with a lab device and a management account.

```
# Only valid when the shared auth cache is missing or malformed:
curl -sS -X POST -d 'noneed=noneed' http://DEVICE/router/reboot.cgi
```

Expected result: In the fail-open cache state, the CGI is executed without valid administrator credentials.

These steps are for vendor/CNA verification on a lab device. They are not a full exploit chain.

## Impact
Reboot, factory reset, admin-secret change, firmware upload, and parameter restore can be reached without a valid administrator account.
