# Stored Cross-Site Scripting via LAN-Controlled DHCP Host Names

- Published: 2026-09-14
- Supplier: Netcore
- Product: NR268
- Affected version: NR268-V1.7.121109.bin
- Vulnerability type: Stored Cross-Site Scripting (XSS)
- Contributors: Zhou Ao, Yin Luxing, Jiang Yuxuan, Liu Xin, @Nebusec

## Summary
Host names learned from LAN DHCP/ARP are later inserted into administrator views and parsed with eval or innerHTML without encoding.

## Affected Component / Code Path
- `DHCP hostname / ARP display views`
- `admin UI eval() and HTML sinks`

## Technical Details
A LAN client can supply a host name that is stored and later rendered in admin pages. The UI executes those strings through eval or HTML sinks.

## Verification
- Tested firmware: `NR268-V1.7.121109.bin`
- Authentication: Write: LAN client via DHCP host name. Trigger: administrator viewing the host list.
- Replace `DEVICE`, `USER`, and `PASS` with a lab device and a management account.

```
# LAN DHCP host name is the injection point. Then open the admin DHCP/ARP list page.
```

Expected result: The admin view executes the stored host name in the router origin.

These steps are for vendor/CNA verification on a lab device. They are not a full exploit chain.

## Impact
A LAN client can execute script in an administrator browser when the admin opens the affected views.
